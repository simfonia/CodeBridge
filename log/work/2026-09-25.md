## 技術深挖 (Technical Deep Dive)

### 新 repository 的必要性
若直接在 `piBlockly-modules` 原地升級，產品名稱、module manifest、CodeBridge runtime contract 與舊 piBlockly loader 會形成混合責任。新 repository 可從一開始建立獨立 schema、CI、發布與安全流程，同時以 migration fixtures 吸收舊模組資產。

### 相容策略
新 repository 不強行立即重命名 block type。Blockly XML 以 block type 儲存，保留既有 type 能降低遷移風險。Module ID 與 block type 分离：前者用於版本、相容與依賴管理，後者用於 workspace serialization。

### Module Runtime seam
主要測試 seam 從 catalog 開始，完整經過下載、驗證、message／block／generator／toolbox 註冊、XML 載入、Arduino code 產生與 source mapping。僅測試單一 blocks.js 或 generators.js 無法驗證遠端模組的實際可用性。

### 工具鏈責任
Arduino CLI 負責 core、library、board discovery、compile 與 upload；Rust serialport 負責長時間雙向序列連線。Serial Plotter 另由 plot parser、series store 與 renderer 組成，不依賴 CLI 提供圖表 UI。

### 技術深挖 (Technical Deep Dive)

#### v13 ARIA 初始化需要官方基礎訊息
Blockly v13 工作區建立時會讀取 `WORKSPACE_LABEL_PLAIN`、`WORKSPACE_LABEL_1_STACK`、`WORKSPACE_LABEL_MANY_STACKS` 與 `WORKSPACE_ROLEDESCRIPTION`。CodeBridge 過去只載入 core 與自訂模組訊息，v12 不需要這些鍵，但 v13 會在 `WORKSPACE_LABEL_MANY_STACKS.replace()` 直接失敗。解法是將官方 en／zh-hant msg UMD 置於 core 之後、modules 之前，並保存 locale snapshot，讓執行期仍能切換語系。

#### Theme 與 Renderer 是不同設定
Blockly 13.3.0 預設 renderer 為 Thrasos，但公開的 `Blockly.Themes` 僅有 Classic 與 Zelos，沒有 Thrasos theme。CodeBridge 固定 `renderer: 'thrasos'`，theme 使用 `Blockly.Themes.Classic`；不可把 renderer 名稱誤傳到 theme 欄位。

#### 音效選項名稱
Blockly injection option 為 `sounds`（複數）。設定 `sounds: false` 後，官方 `Options.hasSounds` 為 false，`inject()` 不會載入 click、disconnect、delete、drop media。AudioManager 物件仍可能被建立，但沒有已載入音效，不會發聲。

#### v13 XML 驗證更嚴格
v12 migration fixture 的 `input_statement` 必須使用 `<statement name="...">`；測試中曾用 `<value name="...">`，v13 會報 `Shadow block is missing previous connection`。產品現有 XML 產生器本來就使用 statement 節點，因此不需變更 block 定義。

### 技術深挖 (Technical Deep Dive)

#### Core-only 不包含標準 mutator extension
Blockly v13 core-only 資源可建立基本工作區，但 `controls_if` 與 `text_join` 的覆寫定義引用 `controls_if_mutator`／`text_join_mutator`。若未先載入官方 `blocks_compressed.js`，建立這兩種 block 會拋出 `Extension ... not found`。因此載入順序固定為 core → standard blocks → language generators → plugins → CodeBridge 覆寫 blocks。

#### v12 controls_if mutation 屬性已變更
v12 fixture 使用 `elseifCount`／`elseCount`，Blockly 13.3.0 官方 mutator 讀取 `elseif`／`else`。在 block definition 覆寫官方 mutator method 會觸發 v13 mixin 防護，因此正確解法是在 XML 輸入邊界統一轉換 mutation DOM，再呼叫官方 `Blockly.Xml.domToWorkspace()`。所有產品載入路徑都必須使用 `CodeBridgeBlocklyXml`，包含 session restore 與 style reload。

#### v13 ARIA workspace label 需明確刷新
Blockly v13 在工作區建立時先產生 0-stack ARIA label。CodeBridge 在 listener 安裝前以 disabled events 注入初始 XML，因此不會自動更新 stack count。修正為正常觸發 events，並在 XML 載入／style reload 後呼叫 `workspace.updateAriaLabel()`，確保螢幕閱讀器讀到實際 block 數。
