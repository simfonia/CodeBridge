### 技術深挖 (Technical Deep Dive)

#### 嚴重缺陷：CodeBridge 的每次真實編譯都會失敗
`arduino-cli` 硬性要求草稿資料夾名與 `.ino` 主檔名**完全相同**。原本資料夾用 `project_id`（`smoke_ok`）、主檔名用 sanitize 後的顯示名（`SmokeOk`），CLI 因此回報 `Can't open sketch: main file missing from sketch` —— 所有專案、所有板子都失敗。

**為什麼 200+ 單元測試全綠？** 既有測試只驗證 `ino_file_name() == stem`，**從未驗證資料夾名與檔名一致**；假 runner 也不檢查檔名規則。這是純邏輯測試的典型盲區——**外部工具的契約必須用真實工具驗證**。

#### 修法：多一層，同時滿足三個約束
直接改用 `stem` 當資料夾名會打破兩項既有行為（都被測試抓到）：同名專案互相覆蓋、改名後舊目錄殘留。因此路徑改為 `build_root/<project_id>/<stem>/<stem>.ino`：最內層滿足 CLI、外層 `project_id` 維持隔離、白名單驗證不變。另加 `purge_stale_sketches()` 處理改名殘留。

#### 隔離設計的代價
CodeBridge 刻意用隔離 config dir（不污染使用者的 Arduino IDE），代價是**看不到使用者已裝的 3 個核心**。不是 bug，是取捨，但首次使用門檻偏高，值得評估「匯入既有核心」的選項。

#### `arduino-cli 1.2.0` 只有 `--config-dir`
實測確認 1.2.0 沒有 `--data-dir`／`user-dir` 旗標。T2 的 `GlobalFlags::prefix()` 只產生 `--config-dir` 是正確的相容做法；目錄隔離需透過 `arduino-cli.yaml` 的 `directories:` 設定。

### 技術深挖 (Technical Deep Dive)

#### 手動選板必須能覆寫既有值 —— 與自動切板方向相反
`board-detector.js` 的自動切板只在 `meta.fqbn` 為空時填入（否則會抹掉上傳前比對的基準）；面板的選取則**一定覆寫**。兩者看似矛盾，實則語意不同：自動切板是「推測硬體」，手動選板是「使用者明確指定」。若面板也拒絕覆寫，使用者將永遠無法改板子 —— 這與 T2-D 的比對需求不可混為一談。

#### 名稱與 FQBN 必須並列
只顯示 `arduino:avr:uno` 對高中生沒有判斷依據。使用者手上拿的是「Arduino Uno」這塊板，兩者並列才確認得了是不是同一顆晶片。搜尋也同時比對兩者，因為使用者可能輸入「uno」也可能直接貼文件中的 FQBN。

#### 搜尋字串在關閉／重開後保留
使用者搜到一半被打斷（插拔板子、誤按遮罩）時，重開面板若清空關鍵字就得重打一次。因此 `term` 是模組狀態而非 input 的暫存值。

#### 關鍵修正：`window.CodeBridgeProject` 是工廠，不是 store
`project-store.js` 匯出 `createStore` 工廠，`setMeta` 只在 store 實例上。原本 `window.CodeBridgeProject.setMeta(...)` 在真實應用中是 `undefined` —— **使用者的選板不會存進 .cbg**。單元測試注入 fake store 而全數通過，是 E2E 把它逼出來。修正：main.js 掛 `window.CodeBridgeProjectStore`，模組改讀該入口。

**單元測試的盲區**：模組若依賴「全域物件的形狀」，fake 會自動符合預期，測試再綠都驗證不到整合錯誤。凡是讀 `window.X` 的地方，E2E 至少要有一條涵蓋。

#### 教訓：先讀再寫，別讓編輯工具吃掉既有測試
本輪曾把 `board-picker` 的 E2E 內容直接寫進 `compile-flow.spec.js` 的開頭，覆蓋了 T2-C 的既有測試。已用 `git show HEAD:<path>` 還原。**新增測試一律建新檔**，不要沿用既有 spec 的 import 區塊當插入點。

### 技術深挖 (Technical Deep Dive)

#### 自動切板會把上傳前比對的基準抹掉
初版 `applyToMeta()` 無條件把偵測到的 FQBN 寫回 `meta.fqbn`，使 `verifyBoardForUpload()` 的 `expected` 與 `detected` 恆等 —— 等於沒有比對。**自動切板現在只在 `meta.fqbn` 為空時填入**。這是被自己寫的測試抓到的：「FQBN 不同時詢問」通過但「FQBN 相同時直接放行」失敗，兩者同時成立就代表比對邏輯不存在。

#### 偏好埠與自動選取必須分開記錄
只有使用者手動選的埠（`change` 事件）才寫入 localStorage；自動選取不覆寫。區分依賴 DOM 語意：`change` 只在使用者互動時觸發，程式直接設定 `value` 不會。

#### `Element.remove()` 不能用來清空下拉
那是把節點從 DOM 摘掉，會讓整個序列埠下拉從工具列消失。正確做法是 `while (element.firstChild) element.removeChild(...)`。

#### 沒有可用埠時只保留原選擇
同時放 placeholder 與保留項會讓下拉出現兩個可選項，使用者會誤以為還有其他埠可選。

### 教訓：PowerShell here-string 會破壞中文字面值
本輪多次用 `@'...'@ | Set-Content -Encoding UTF8` 寫暫存 Python 腳本時，中文字面值被寫成錯誤位元組，導致替代字串比對失敗（誤以為是 CRLF 問題）。**含中文字串的批次改寫一律用 editor 工具**，Python 腳本只保留給純 ASCII 的替換。若必須用 Python，中文字面值應以 `\uXXXX` 轉義表示。
