## 後續異動：修復程式碼縮排雙重縮排問題

### 問題診斷
- **現象**：setup() 和 loop() 內的程式碼縮排為 4 個空格（預期為 2 個）
- **根本原因**：雙重縮排
  1. `statementToCode()` 已經自動加入縮排（Blockly 內建功能）
  2. `finish()` 中的 `prefixLines()` 又再次加入縮排
  3. 結果：2 + 2 = 4 個空格

### 解決方案
1. **在 `_core.js` 的 `init()` 中初始化 `INDENT`**
   - 加入 `Blockly.Arduino.INDENT = '  ';`（兩個空格）
   - 符合 Blockly 標準做法

2. **修改 `_core.js` 的 `finish()` 函數**
   - 使用 `Blockly.Arduino.prefixLines()` 統一處理縮排
   - setup() 和 loop() 內的程式碼透過 `prefixLines(code, Blockly.Arduino.INDENT)` 加入縮排

3. **修改 `generators.js` 的 setup/loop 產生器**
   - 將 `statementToCode()` 改為 `blockToCode()`
   - 避免 `statementToCode()` 自動加入的縮排
   - 讓縮排邏輯集中在 `finish()` 統一管理

### 修改檔案
- `ui/src/lib/blockly/generators/_core.js`：備份 + 初始化 INDENT + 修改 finish()
- `ui/src/lib/blockly/modules/arduino/generators.js`：修改 setup/loop 使用正確的 blockToCode() 方式
- 備份位置：`ui/src/lib/blockly/generators/backup/_core_backup_20260726_122325.js`

### 技術細節
- Blockly 的 `statementToCode()` 內部會呼叫 `prefixLines(code, this.INDENT)`
- `blockToCode()` 返回原始程式碼，不含縮排
- **重要**：`blockToCode(block, 'INPUT')` 是錯誤用法，會導致無限遞迴
- **正確用法**：先取得目標 block，再呼叫 `blockToCode(targetBlock)`
  ```javascript
  var contentBlock = block.getInputTargetBlock('CONTENT');
  var code = contentBlock ? Blockly.Arduino.blockToCode(contentBlock) : '';
  ```
- 使用 `prefixLines()` 確保縮排邏輯集中管理，符合 DRY 原則

### 修復歷程
1. 初次嘗試：使用 `blockToCode(block, 'CONTENT')` → 無限遞迴 ❌
2. 恢復使用 `statementToCode()` → 雙重縮排（4 個空格）❌
3. 最終解法：使用 `getInputTargetBlock()` + `blockToCode(targetBlock)` → 正確 ✅

## 修復：coding_comment 頂層產生在 loop() 問題

### 問題
coding_comment 積木放在頂層時，產生的註解會跑到 loop() 裡面，而非全局作用域。

### 根本原因
coding_comment generator 直接返回程式碼，頂層積木的返回值會被拼接到 finish() 的 code 參數中，進而放入 loop()。

### 解決方案
檢查 block.getParent()：
- 若父積木為 initializes_setup 或 initializes_loop：直接返回程式碼（放在函式內）
- 若為頂層：放入 definitions_ bucket，由 finish() 放在全局作用域
