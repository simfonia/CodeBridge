CodeBridge 序列監視器（Serial Monitor）

計畫文件：log/plan/SerialMonitor.md（2026-09-28 實作）

設計約束（動工前必讀）

  • 序列埠是獨佔資源：Windows 上同一個 COM 埠只能被一個程序開啟。 Monitor 與 avrdude 共用 AppState::port_lease。 新增任何會持有埠的功能都必須走這把鎖，不可各自 opens。
  • 共用面板：序列輸出與編譯輸出都進 #terminalContent， 以 kind: 'data' vs 'command' 視覺區隔。 terminal-panel.js 是純面板，不可 塞入 Monitor 邏輯。
  • baud 變更必須重啟：序列埠 baud 在 open() 時綁定， 沒有熱改 API。
  • 上傳後自動重連預設開啟（2026-09-28 決策）。

前端公開 API

API用途
CodeBridgeSerialMonitor.init({ store })綁定控制列、訂閱兩個事件、同步面板外觀。
start({ port, baud, hex })啟動；未給 port 時取工具列下拉。無埠時不發動後端，直接回 false。
stop() / toggle()停止／切換。
setBaud(n)已連線時重啟；未連線時只記住設定不發動後端。
setHex(b) / setTimestamp(b)純前端顯示切換，不重啟、不呼叫後端。
send(text) / submitInput()送出開發者輸入行（後端自動補 \n）。
handlePortsChanged({ ports })由 board-detector.onChange 轉呼叫；監看的埠消失時自動關閉。
SUPPORTED_BAUDS與 arduino 模組積木 BAUD dropdown 一致（刻意不建 i18n key）。

Tauri command

Command說明
serial_monitor_start(port, baud?, hex?)開啟序列埠並啟動讀取 thread。會先停止既有 session（重複點等同重啟）。埠被作業佔用時回 CLI_ERROR_PORT_BUSY|。
serial_monitor_stop()停止讀取並清除 wants。回傳是否真的有 session 在跑。
serial_monitor_send(text)寫入一行；未開啟時回 SERIAL_MONITOR_NOT_RUNNING|。
serial_monitor_status()回傳 { connected, port, baud, error }；有 wants 但未連線 = 上傳暫停中。

事件

事件Payload
codebridge://serial-data{ port, lines[] } —— 批次而非逐行，避免高流量塞爆 IPC。
codebridge://serial-state{ connected, port, baud, error }；thread 結束（拔線／停止）也會送。

Rust 純邏輯（可獨立單元測試，不需硬體）

型別／函式說明
LineFramer::push(&[u8]) -> Vec<Vec<u8>>位元組緩衝切行。回傳原始位元組：HEX 模式需要未解碼的內容，先解碼再重編碼會失真。剝除行尾 \r，超過 MAX_LINE_BYTES 強制切斷。
hex_encode(&[u8]) / format_line(&[u8], hex)空格分隔大寫 HEX（保留前導零）；文字模式走 encoding::decode_output 的 fallback 鏈。
pump<R: Read, F: FnMut(Vec<String>)>(...)讀取迴圈。泛型化 Read 是為了讓測試用 Cursor 完整驗證切行、停止旗標、讀取錯誤，不需真實硬體。收尾會 flush 殘餘行與未送出的行。
serial_flush_policy()60ms / 32 行（比編譯的 200ms / 64 行快 —— 序列資料對延遲敏感）。
MonitorConfig::new(port, baud)不支援的 baud 退回 DEFAULT_BAUD；is_valid() 檢查埠名非空。

常見錯誤對照（實機驗證抓到的）

症狀根因處置
SERIAL_ERROR_READ|Operation timed out，
Monitor 一開啟就死		 SerialPort::timeout() 到期回的是 Err(TimedOut)，語意是「沒資料」不是「失敗」。把它當斷線 break，板子安靜 50ms 就死。 用 is_no_data() 區分 TimedOut／WouldBlock 與真斷線。
關閉後立即重開 →「無法開啟序列埠」
切 baud 也失敗、上傳前沒自動關閉		 stop 只設旗標就返回，讀取 thread 仍活著、SerialPort 仍持有 Windows COM handle → AccessDenied。 停止路徑必須 JoinHandle::join()，再加 120ms 冷卻讓驅動釋放。
baud 設錯時「完全沒反應」，
切回來才看到累積亂碼		 LineFramer 只在遇 \n 才吐行；錯 baud 下位元組邊界錯位，換行符極少出現，資料全卡在緩衝。 IDLE_FLUSH_MS = 250：閒置逾時強制切出殘餘位元組（對齊 Arduino IDE）。
狀態列「已接收 N bytes」
但文字全部空白		 baud 不符 → CH340 取樣時脈錯誤 → 垃圾位元組 → decode_output 的 Big5 分支是總函式（任何位元組序列都能「成功」解碼）， 垃圾被解成控制字元（0x00–0x1F），終端機裡完全不可見。 make_control_chars_visible()：把不可列印字元轉成 <0xNN>， 讓「波特率不符」從不可診斷變成一眼可辨。
收合終端機面板後
Blockly 工作區沒有變大		 Blockly 的 SVG 只在 inject() 時量一次尺寸，不會自己察覺容器變化。程式預覽面板有呼叫 svgResize，終端機面板漏了。 terminal-panel.onWorkspaceResize(listener)，main.js 註冊為 Blockly.svgResize。
上傳後狀態燈停在「上傳暫停中」 start_session() 從未送出「已連線」狀態；重連失敗時又是 let _ = 完全靜默。 成功時 emit SERIAL_STATE(connected)；失敗時 emit failed。
上傳鈕不會變灰 #btn-run 是 <div>，而 HTML disabled 只對表單元素有效： div.disabled = true 不會產生 [disabled] attribute，CSS 永遠匹配不到。 改為 <button type="button"> + .toolbar-btn 補瀏覽器預設樣式 reset。

AppState 新增欄位

  • serial_monitor: Arc<Mutex<Option<Session>>>：進行中的 session（最多一個）。
  • monitor_wants: Arc<Mutex<Option<MonitorConfig>>>：使用者「想」監看的設定。 與「是否連線」分離：upload 會暫時關閉 Monitor，但使用者沒有關閉它的意圖； 若只有一個狀態，上傳結束後就分不清「要重連」與「已手動關閉」。
  • monitor_thread: Arc<Mutex<Option<JoinHandle<()>>>>：讀取 thread 控制代碼。 沒有它就無法確保序列埠真的被釋放（見上方「常見錯誤對照」）。

埠租約協調流程

upload_start
  → release_port_for_upload(port)   // 只在 wants.port == port 時中斷
  → try_acquire_port(port)
  → ...avrdude...

上傳終態
  → release_port(port)              // 必須先釋放
  → sleep(150ms)                    // Windows 驅動釋放 handle 需要時間
  → 若 lease 空閒 → start_session()

常見錯誤：在 release_port 之前重連， 會撞到自己剛拿到的鎖；或省略 150ms 冷卻，得到 AccessDenied。
